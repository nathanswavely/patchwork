**If you are on v0.26.0, your community map is blank — markers on an empty
rectangle, no streets. This release fixes it.** Pull it.

v0.26.0 moved maplibre-gl from 5 to 6 to close a critical advisory, which was
the right thing to do. MapLibre 6 parses vector tiles in a separate worker file
and locates that file by building a URL at runtime, which the bundler cannot
see and therefore never emitted. Every map Patchwork drew asked for a worker
that was not there, got the SPA's index.html instead, and parsed no tile ever.
The fallback to plain raster tiles — which exists for exactly this, a map
showing nothing — did not fire either, because it was watching for a painted
frame and an empty frame is still a frame. It now waits for a parsed tile.

The second half of this release is unrelated to the first and has been true far
longer: nothing between Patchwork and the browser ever compressed anything.
Caddy only reverse-proxies, and Go's file server does not compress, so a cold
visit to the map carried about 3 MB of JavaScript, CSS and JSON in full. The
binary now gzips its own responses, and the hash-named files under `/assets/`
carry a cache lifetime, so a returning visitor fetches almost nothing.

Together: the map page goes from roughly 3 MB and no map to roughly 870 KB and
a map.

## Upgrading

Nothing to do. `docker compose pull && docker compose up -d`.

No migrations run. The previous image reads the same database, so rolling back
is available — it just gives you the blank map again.

Compression happens in the binary rather than in the bundled Caddyfile, so an
instance running Patchwork behind its own proxy, or behind none at all, gets it
too. If your proxy compresses already it will leave these responses alone; they
arrive declaring their encoding.

Worth one look after you pull: open `/map` and confirm you see roads. The
failure this fixes was a 200 response that was not what it claimed to be, and
that is not a thing a test suite noticed.

## Changes

- The map's tile worker is bundled and handed to MapLibre explicitly, instead
  of being guessed at a URL that did not exist.
- The raster fallback proves the map alive with a parsed tile rather than a
  painted frame, so a renderer that draws nothing is caught rather than
  congratulated.
- Responses are gzipped: the frontend bundle, the stylesheets, the API's JSON,
  the ICS and RSS feeds, the ActivityPub documents. Fonts, images and an
  admin's export zip are left alone — they arrive compressed already.
- Files under `/assets/` are marked immutable. Their names contain a hash of
  their contents, so a new build is a new name and the old one never changes.
