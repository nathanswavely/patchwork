Three pull requests since v0.35.2 and one migration (two added columns and
a cleanup of answered request notifications). No config, volume, port or
Caddy changes, so this update is the image pull alone.

## Built on Go 1.26.11

Go 1.26.10 and earlier carry GO-2026-6859, a race in `net/http` that can
crash an HTTP/1 server. Every image up to v0.35.2 was built on an affected
Go. This one is built on 1.26.11, where it is fixed (#476, #478). The image
is the only thing that changes; there is nothing to configure.

## A join request's notification goes when the request is answered

Approving or rejecting a join request, or the requester withdrawing it, now
takes the "Membership request" line out of every admin's bell. Before, the
line outlived its answer and the unread badge kept counting it, so the bell,
the badge and the queue could each give a different number (#476).

A follower asking to become a member of an approval-required patch was
announced to admins as "New member joined", with no request line to answer
from. It now sends the request line.

## An invitation says who sent it

An invitation records the admin who made it. The invited person reads the
name on the patch page and on their Dashboard, and the patch's admins read
it beside each outstanding invitation. An invitation made before this
release shows no name. The name goes when the invitation is accepted (#476).

The Members tab now lists outstanding invitations below the members, to the
patch's own admins only. An invited person is still counted nowhere.

## The Dashboard says what needs you

"Attention Needed" is replaced by three sections (#476):

- **Needs you:** invitations to answer, join requests to answer, and votes
  owed, one line per patch.
- **Waiting on an answer:** your own pending requests, with the date sent.
- **Coming up:** events on your patches.

## Smaller changes

- Patch Settings → Members is renamed **Roles and requests**. Its address is
  unchanged, and the Members tab links to it for admins (#476).
- The role chip menu reads Settings, Notifications, then Leave. For a member
  or follower the first two open their own My Patches and notification
  preferences (#476).
- My Patches says "Contact: not shared" or "Contact: N shared" for each
  patch (#476).
- The role mark on a quilt tile has an accessible name, and the tile's hover
  tip says the same thing in words (#476).
- Page titles separate the page from the quilt's name with a pipe, and the
  privacy and terms pages lose their "The fine print" label (#473).

## For client developers

Nothing here breaks a client built against v0.35.2. All of it is additive
or a change a client can ignore:

- `invited_by` on each item of `GET /api/v1/users/me/invitations`, and on
  each item of `invited` in `GET /api/v1/nodes/{slug}/members` (sent to the
  patch's admins only, as before). An object of `id`, `username` and
  `display_name`. All three are empty strings for an invitation made before
  this release, and `username` is empty when the inviter has deleted their
  account (#476).
- `invited_by` and `invited_by_name` on each row of `memberships` in
  `GET /api/v1/users/me/export`, null except on an open invitation (#476).
- `invited_by` in `memberships.json` in both seamrip archives. An archive
  without it still imports (#476).
- A `membership.request` notification is deleted once its request is
  approved, rejected or withdrawn, so an id a client is holding can
  disappear from `GET /api/v1/notifications` and the unread count can fall
  without the client marking anything read (#476).
- A follower asking to join an approval-required patch now produces
  `membership.request` for admins where it produced `membership.joined`
  (#476).
- The `og:title` of patch and event pages uses ` | ` in place of an em dash
  before the quilt's name (#473).

From this release on, every release's notes carry this section and a
`client_breaking` flag in `release.json`
(`docs/adr/2026-11-11-a-release-says-what-it-means-for-clients.md`, #478).

## Upgrading

**Take a backup first**, then:

```sh
docker compose pull patchwork && docker compose up -d
```

One migration runs. It adds `notifications.membership_id` and
`memberships.invited_by`, both nullable, and deletes the "Membership
request" notifications whose request has already been answered: those on a
patch with no open request, and those older than every request still open
on their patch.

No `git pull` is needed; nothing outside the image changed.

**Rolling back to v0.35.2 is not clean.** The older binary refuses to start
against a database whose `schema_migrations` names a migration it does not
know, and the deleted notifications are not restored by repinning. To go
back, restore the backup taken above rather than starting the older image
against this database.
