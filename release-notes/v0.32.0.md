Thirty-seven pull requests since v0.31.0, four decision records, two
migrations. Both migrations add columns and a table; neither rewrites
anything. No config key is renamed or newly required, but the compose file
and the `Caddyfile` changed, so this update wants a `git pull` and a Caddy
restart as well as the image pull (see Upgrading).

## A page made for someone tells them so

A young quilt is mostly unclaimed patches, made by the admin from what is
already public, and nothing told their owners the page existed. Now each
unclaimed patch can get one **intro**: an email sent by an instance admin,
after reading the whole message, to a contact address a person entered.
Nothing sends on creation, nothing discovers addresses, and there is no
send-all.

- **Patch Settings → Intro** on an unclaimed patch holds the contact
  address (an instance admin, or a trusted contributor whose grant reaches
  the patch, may enter it) and, for the instance admin, the preview and
  send. Preview reads the patch's website once to decide which calendar
  paragraph fits: their own calendar is already syncing, events arrive
  secondhand through an aggregator, a Squarespace site one page type away
  from a feed, a WordPress site with no feed, a site with nothing to
  subscribe to, or no site at all. It says why it picked, and the admin can
  pick another, edit the text, and send. One send per address; a second is
  an explicit resend.
- **Administration → Settings → Outreach** is the backlog (every unclaimed
  patch, who has been written to and who has not) and the template: a
  shipped text with placeholders, replaced part by part per instance the
  way the legal documents are, plus the switch that turns the feature off
  for a quilt that would rather write to nobody who did not ask first.
- **An intro sent to the patch's verification domain carries a claim
  link.** The link holds a 30-day single-use token that stands in for the
  email leg of a claim: whoever follows it, signed in as themselves, holds
  an approved claim and goes straight to setup. It signs nobody in, and
  changing the address revokes any unused token. An address at any other
  domain gets the ordinary claim page.
- **Without SMTP the preview is still the product**: the message renders
  with a copy button, and the admin records that they sent it by hand.

`nodes.contact_email` and the `intro_sends` table are workspace-only and
stay behind at the seamrip boundary. The decision is
`docs/adr/2026-10-16-a-page-made-for-someone-tells-them-so.md` (#404).

## The design system is Liquid Textile

Patchwork's tokens, global classes and behaviours now come from Liquid
Textile, vendored under `web/src/vendor/liquid-textile/` and changed only by
`scripts/sync-lt.sh`. Fields, buttons, pills, tags, dialogs (on native
`<dialog>`), menus, toasts, two-step confirms, tab rows, the theme store and
the base element rules all moved across in steps (#374 to #397). The light
theme is warm white. Nothing changes in the data or the API; what changes
is that every control on the site is now the same control. Decision:
`docs/adr/2026-10-11-the-design-system-is-liquid-textile-vendored.md`.

Alongside it, **the admin panel, Patch Settings and the patch workspace
work on a phone** (#363): one level of navigation on screen at a time
instead of two horizontal scrollers, a bottom tab bar for the workspace,
touch targets on the block drafter, the fabric wall and the map picker,
and the menus and buttons that folded their own labels no longer do.

## A sign-in link knows where it was asked for

Asking for a magic link now sets a short-lived cookie in the browser that
asked, and the emailed link opens a page rather than spending itself on
load. The browser that asked is signed in as before. Opened anywhere else
(another device, a mail client's preview, a scanner that fetches every
link first), the page shows the six-digit code to type where sign-in was
asked for, and spends nothing. "Sign in on this device" is the one act that
spends the link. The old `/api/v1/auth/verify/{token}` addresses redirect to
the page, so a link already in someone's inbox still works (#364).
Decision: `docs/adr/2026-09-28-a-link-knows-where-it-was-asked-for.md`.

## For deployers: your Caddy config has a home

The `Caddyfile` is tracked, so an edit to it made the next `git pull`
refuse and a `git reset --hard` undid it silently. Your own Caddy
configuration now lives in `caddy.d/`, ignored by git and mounted read-only
into the caddy container: `*.caddy` files for blocks of their own, `*.site`
files for directives inside the Patchwork site. The access-log recipe is
`caddy.d/access-log.site.example` (#402). A commented `www` redirect block
is in the `Caddyfile`, with the order of operations that keeps Caddy from
retrying a doomed certificate order (#401). Decision:
`docs/adr/2026-10-16-a-deployer-never-edits-a-tracked-file.md`.

`server.host` (or `PATCHWORK_HOST`) names the interface to bind. Unset
still means every interface, which the Docker image needs; development
runs set `127.0.0.1`, which is also what stops Windows Firewall asking
about every fresh build (#393).

## Smaller things

- **Event sources:** a web page that trips the ICS decoder is now an
  ordinary "web page, not a calendar" error rather than a panic that could
  take the hourly worker down (#399). The Events Calendar's list export is
  read when its other exports answer empty, as a `tribe` source (#370).
  Each source's settings sit under it on the page.
- **Look at your own page without signing out:** `?as=visitor` on any
  page shows it as a signed-out stranger sees it, computed by the same
  gates rather than a second opinion (#355).
- **After you vote,** the voters list refreshes with the counts instead of
  keeping its pre-vote snapshot (#356). The proposal page's summary agrees
  with the thing it summarises (#351), rules can be read without entering
  the editor (#352), and an election is called one word everywhere (#353).
- **The button that saves the group:** the two downloads on account
  settings now say whose data each one is, and the member seamrip leads
  with plain words (#354).
- **A patch you cannot reach** reads as what it is, not as a loading
  error (#350).
- **Security:** Go 1.26.9 and `x/net` v0.60.0 clear ten advisories;
  `source-map-js` 1.2.2 clears one more (#371).
- **Copy ledger:** the review tooling moved to the published SlopChop
  package, pinned to 0.2.1 (#372).

## Upgrading

**Take a backup first.** Then, because the compose file and the
`Caddyfile` changed in this release:

```sh
git pull
docker compose pull patchwork && docker compose up -d
docker compose restart caddy
```

`up -d` recreates the caddy container on its own when the compose file
changed; the explicit restart is for the single-file `Caddyfile` mount,
which otherwise keeps reading the old file. Expect two warning lines from
Caddy about `caddy.d/*.caddy` and `caddy.d/*.site` matching nothing. They
are the shipped state.

Two migrations run: two columns on `magic_links`, and one column on
`nodes` plus the `intro_sends` table. All additive.

**Rolling back to v0.31.0 is not clean**, for a different reason than
last time: nothing in the data is lost, but the older binary refuses to
start against a database whose `schema_migrations` names a migration it
does not know, which is what this database will be. To go back, restore
the backup taken above rather than starting the older image against this
database.
