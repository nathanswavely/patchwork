Twenty-four pull requests since v0.30.0, three decision records, five
migrations — one of which rebuilds the `events` table, which is why the
rollback section below is worth reading before you pull. No config key,
volume or port changes.

## Events say who they are for, within what the patch allows

An event's `visibility` is now one of `public`, `followers` or `members`,
and a patch's `follower_permissions.events` switch is a **ceiling** enforced
on every read path in Go, rather than a switch that only hid a tab. With the
switch off, a `followers` event reads as `members` and the event form offers
only the two tiers, with one line saying the patch set it. Event sources
carry a default tier applied at insert. `docs/adr/2026-09-19-an-event-says-
who-it-is-for-within-what-the-patch-allows.md` is the decision.

Two consequences you may notice:

- Events uploaded by CSV as `private` or `unlisted` are now `members`. That
  is the non-exposing direction; nothing that was hidden becomes visible.
- A follower on a patch with the switch off now sees the patch's Events
  tab, showing its public events only. Those events were already on the
  quilt, the map, `/events`, the ICS feed and every direct link, so the
  hidden tab withheld nothing while implying it did (#339).

`POST` and `PATCH /api/v1/events` now refuse a bad `visibility` with a 400
instead of letting SQLite's CHECK constraint answer with a 500, and the
single-event read and its ICS share one gate (#330).

## A sign-in code beside the magic link, and an instance that vouches for an app

Every magic-link email now carries a six-digit code as well as the link.
`POST /api/v1/auth/magic-link/verify` with the address and the code signs in
exactly as the link does — the session cookie, or a signup token for a new
address — for a client that cannot receive the link in its own session: a
native app, a CLI, a second device. Five wrong codes burn the code and the
link together; every failure is the one sentence `invalid or expired code`,
so the endpoint cannot be asked whether an address was ever requested. The
web's own "Check your email" panel accepts the code too, and an instance
without SMTP prints the code under the link in its log.

A new page, **Administration → Settings → Apps**, lists the native apps
this quilt vouches for. Listing one publishes the platform association file
that lets that app hold this domain's passkeys — Apple's
`/.well-known/apple-app-site-association` and Android's
`/.well-known/assetlinks.json` — rendered only from what an admin listed.
Nothing is listed unless you list it, and while nothing is listed both
addresses answer 404, so an instance that never asked for this serves
nothing platform-shaped. Adding an app is step-up gated, because it lets
that app invoke your domain's passkeys; removing one is not. Both are
audited. The project's own client is not pre-listed anywhere: a reference
app is one row an admin adds, and a fork lists its own.
`docs/adr/2026-09-20-an-instance-vouches-for-an-app.md` says why.

## The admin panel is five tabs

Fifteen top-level tabs became five, each answering one question: Overview,
Review (reports, patch and event submissions, claims, suggested tags),
Users, Settings (quilt, label, legal, tags, neighbors, aggregators, usage,
archived patches, prove admin, apps) and Audit log. Section URLs are the
tab's plus one segment, and every old flat URL redirects, so bookmarks and
the links in older notifications still land (#308,
`docs/adr/2026-09-17-an-admin-tab-answers-one-question.md`).

## What the governance simulation found

The fifth epoch of the governance simulation (docs/adr/096) and the
September rollout's own conduct produced most of this release. Each of
these is one finding, fixed where it was found:

- **The council answers the roster's question** (#335). A patch that
  withholds its member list was still naming its seat holders, with term
  dates, to a signed-out reader, two sentences under "does not list its
  admins publicly". The seats now withhold their holders under the same
  rule as the admin list.
- **A contest says what it did, and why** (#337). A failed election said
  "Settled nothing." It now carries its turnout and says "Quorum not met:
  1 of 4 voted, 2 needed", while the ballot is open as well as after.
- **A ballot a voter can use** (#346). Standing takes an optional statement
  of up to 500 characters that renders beside the name, and a voter can
  abstain on the record rather than being indistinguishable from someone
  who never voted. Migration: a `statement` column and an
  `election_abstentions` table.
- **The council page offers what it describes** (#341). A vacant chair
  whose route is nomination now carries "Nominate a member", and the form
  opens on the type that was clicked.
- **A record of who came off** (#344). A seat vacated for inactivity, an
  interim promotion, and an admin made or unmade by another person now
  appear in the patch's governance record, drawn from the audit log, for
  the people the record already answers to.
- **When Patchwork changes your patch, it says so to somebody who exists**
  (#342). The September default-closing notice went to admins only, so an
  admin-less patch was told nobody; it now goes to all members, and it
  names every key it moved rather than the one it chose to mention.
- **When two pages disagree** (#349). The inactivity rule was stated three
  ways on three pages; each now names the mechanism that runs, with both
  its numbers, and the warning names the day.

## Smaller things

- **A date says which year** once the year stops being implied, and eight
  call sites that printed `8/15/2026` now use the app's one date format
  (#340).
- **On a phone**, the workspace tab strip fades where it continues and
  scrolls the active tab into view, and the contact-sharing sentence has
  its noun back (#343).
- **Gazetteer:** a house number only scores on a street the query named,
  so `150 N Prince St` no longer suggests a garage on East King; a one-word
  venue name such as `Tellus360` is answered; and the documented build
  path now starts from the `.osm.pbf` Geofabrik actually ships, with real
  timings (#331, #333, #334).
- **An aggregator listing keeps the feed's URL** on the way back out, so
  aggregator-routed events regain their original link on the next hourly
  sync (#345).
- **`cmd/export` opens the database read-only.** Run from a newer checkout
  against a live instance it used to checkpoint and migrate the file the
  running container was still serving (#328).
- **The quilt:** seams take their colour from the theme rather than a
  hardcoded black, and the desktop patch list is one glass card with a
  hover that dims the rest (#347, #348).
- **CI:** `npm audit signatures` runs in its own job, and a missing
  registry key is reported as what it is rather than as a bad signature
  (#327, #338).

## Upgrading

**Take a backup first.** The events migration rebuilds the `events` table
(all columns and indexes are carried over, and every child table is
re-pointed), then:

```sh
docker compose pull patchwork && docker compose up -d
```

Five migrations run. The other four add columns with defaults and one new
table, which an older binary ignores.

**Rolling back to v0.30.0 is not clean.** The rebuilt `events` table holds
`followers` and `members` where the older binary expects `private` and
`unlisted`, and a `private`/`unlisted` row cannot be told apart again once
it has become `members`. To go back, restore the backup taken above rather
than starting the older image against this database.
